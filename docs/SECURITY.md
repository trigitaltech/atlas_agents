# Security design and limits

## Enforced controls

- Every execution requires explicit backend-enforced consent and starts with its canonical exact target hostname. Extra hosts require fresh approval bound to an observed redirect from a stopped job for the same URL. Existing static entries remain usable targets/filters; no global or wildcard scope is created. See [the complete gate map](PER_EXECUTION_AUTHORIZATION.md).
- Only HTTP/HTTPS, standard ports, and credential-free target URLs. Local, loopback, link-local, private, reserved, multicast, and other non-global DNS answers are denied. Mixed public/private DNS answers fail closed.
- Every HTTP request resolves and validates the hostname after robots/rate-limit waits and immediately before connecting; the TCP connection uses the chosen validated IP with the original Host header and TLS SNI. Proxy environment variables are ignored. Redirects are manual, limited, and revalidated; both original and destination pages get robots checks.
- robots.txt is cached per origin within an execution. 404 permits crawling; other inaccessible statuses fail closed. Disallow, crawl delay, and request rate rules apply. Redis coordinates the minimum domain interval across workers; Redis failure does not open a fallback bypass in normal mode.
- Decompressed responses and rendered HTML have size limits. Page, depth, time, frontier, redirect, token, and browser-resource bounds prevent unbounded workflows. The browser allows at most 30 requests per render; robots and resource requests are separate from the page count.
- Fetching uses GET only. No authentication, CAPTCHA bypass, paywall bypass, clicks, credential reuse, or scraping form submission tools exist. Playwright forms/popups are disabled; non-GET requests, service workers, websockets and uncontrolled subsequent navigation are blocked. HTTP resources are fulfilled through the same pinned-IP fetcher, never direct browser route continuation.
- Website content is untrusted data. Executable markup is removed from extracted text. The LLM has no tool access and receives a fixed system instruction and closed schema. Text cannot choose tools, change domains, or access environment variables. Every non-null extracted value must have a verbatim evidence quote in cleaned source text. Duplicates are removed before storage.
- Provider credentials remain backend-only. API errors do not include provider response bodies or credential headers. The optional bearer token gates application endpoints. Compose exposes only loopback-bound API/frontend ports. CSV output neutralizes spreadsheet formula prefixes.

## Ollama provider credentials

`OLLAMA_API_KEY` is backend-only, required for explicit Cloud mode and optional in local/native-schema mode. It is represented as a secret, excluded from Settings exports, and sent as a bearer header only over HTTPS. Local unauthenticated HTTP remains supported. Provider URL userinfo/query/fragment and redirected requests are rejected. Upstream transport/authentication/JSON/schema errors are sanitized before logging or persistence; reflected credentials are rejected. Agent input schemas forbid credential fields. The provider URL is an operator-controlled connection independent of the restrictive public crawl allowlist. Cloud mode omits provider schema enforcement, parses one JSON object with server-side type/field validation, and nulls every value without matching source evidence using the shared validation rule. It requires the exact official HTTPS base origin to avoid unintended credential destinations. Local mode retains native schema output. See [OLLAMA.md](OLLAMA.md) for compatibility and setup.

## Remaining boundaries

Per-execution confirmation is an operator attestation and cannot establish external permission. Only crawl sources you have permission to access. Public IP checks are application controls; deploy a deny-private egress gateway/firewall as an independent boundary, particularly when running Chromium against hostile websites. Browser request interception is not an OS-level network sandbox and does not prove the absence of browser background networking, browser vulnerabilities, WebRTC/UDP traffic, or side effects behind a server's GET route. Run workers in isolated, patched containers with memory/CPU/process limits, no sensitive mounts, and restricted egress. JavaScript rendering defaults off for this reason.

Source evidence establishes provenance, not factual truth. A hostile page can contain convincing false statements, PII, or instructions; prompt separation and exact quote validation reduce injection impact but cannot guarantee extraction semantics. Extraction is deliberately conservative and may return null for paraphrases, normalized values, or facts outside the bounded text window. No anti-malware or content moderation pipeline is bundled.

Tokens use conservative estimates and provider-reported totals; a timeout/retry may still be billable without exact usage. Approximate prices are operator-configured rather than hardcoded. Enforce account-level provider spend caps independently. HTTP size checks happen after a bounded decompressed chunk is yielded, so they are not a hard process-memory limit.

The MVP is a single trusted workspace with optional shared bearer authentication. There is no user isolation, per-user authorization, audit retention policy, per-client ingress limit, or queue quota. Add these before shared/public operation. Run TLS at the ingress and provision a strong API token and database credentials. The defaults are for loopback development. Back up the database; keep Redis and PostgreSQL unreachable from the public network. Frontend results render as escaped React text; raw source HTML is not rendered in the dashboard.

Cancellation is cooperative. In-flight network/provider requests are bounded by tool/request timeouts and may finish after status changes. Results committed before cancellation remain visible. Atomic conditional updates prevent cancellation from being overwritten by normal completion. Duplicate task claims are rejected. Queue publish and database commit are not a distributed transaction; an ambiguous broker timeout can leave a retained failed job. A transactional outbox is the recommended next improvement.

Browser support is limited to public read-only pages and same-allowlist GET assets. It is not intended for authenticated sessions or full browsing automation. Schedule rows are reserved for future use; no background scheduler is enabled. JSON logs support OpenTelemetry fields but do not configure an exporter or collector.
